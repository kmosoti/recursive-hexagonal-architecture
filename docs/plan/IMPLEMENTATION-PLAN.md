### 2.2 Operating method (revision 2)

- **M1, authority** (§11.7.2). Infrastructure permissions cap execution. `.rha/policy.toml` defines acceptance. This plan is the authorized task list. Guides help. The Executor must not edit the spec or its §1.4 table. It must not read held-out material, report `passed` for a check that did not run, or weaken a test without the §9.14 justification. It must not touch a protected surface without a quoted approval, or invent versions, SHAs or output.
- **M2, the packet.** A packet is one branch, `chg/<first-id>-<slug>`, and one PR. It covers one or more of revision 1's CHG ids, which keep their numbers because records and code cite them. It has one task record with `covers = [...]` and one change record in the §11.7.5 template. It is built as **stages**. A stage is a commit series that ends with the tree green under `cargo nextest run` and `cargo xtask docs --check`. A stage that fails its gate is repaired inside the packet (§11.7.10 repair attempts), not in a follow-up PR. The first commit is the previous item's acceptance record. The merge is the acceptance.
- **M3, one writer.** The task record's `[[work]] claim` names the writing session. Every other session is read-only on that branch. Pull `--ff-only` before every push. Keep no parallel JJ bookmark with the branch's name.
- **M4, scope and layout.** Before the PR, `cargo xtask scope --task <id>` compares `git diff --name-only <base>...HEAD` with the task record's `owned_scope` globs and the §4 layout. A path outside either fails. Widening scope is a task-record decision quoted from Kennedy, recorded before the change.
- **M5, evidence discipline.** Regenerate docs, then run the lane, then commit. Take **one** local L0 record per packet, on the settled clean head, plus the packet's own harness records (H4, H5, bench). Keep failed and superseded records; never rewrite them. Do not commit PR-head CI records; the CI run is visible on the PR. The next acceptance record downloads and commits the record of the run on `main` at the merge.
- **M6, review.** When the packet is ready, run one local Codex review: `codex exec -m gpt-5.6-sol -c model_reasoning_effort=medium -s read-only`, with the packet's checklist. Findings are judged by AGENTS.md. Every confirmed finding gets a determination in the change record and a repair. Re-reviews see only the repair diff. After three rounds, remaining disagreements go to Kennedy. The approval is advisory and is posted on the PR; the merge is Kennedy's.
- **M7, registration before data.** Every graded corpus (H4 module level, markdown witnesses, verifier conformance, bench decisions) is committed, or committed by digest, before the code it grades runs on it. A registration review lists, for each fixture, every finding its shape necessarily triggers under the current rule catalogue, and registers each as a witness or an `expected_findings` entry.
- **M8, computed provenance.** Digests, counts and identities in records come from tools, never from typing. Until P-B's lint exists, a record that states a digest is checked by the reviewer against the file.
- **M9, shell hygiene.** Scripts run under `set -euo pipefail`. Stage paths explicitly. After `git rm`, never `git add` the removed path. History is never rewritten; a wrong commit is disclosed in the change record.
- **M10, decisions.** Status lives in `.rha/decisions.toml`. Reports cite ids and do not restate questions. A gate (§8.1) is a decision point inside a packet: the Executor stops, asks, and records the answer in the task record before continuing.

**Recommended assignment** (Kennedy's direction, 2026-09-22): Claude Opus 5.5 as Executor for packets; the local Codex CLI with Sol at medium effort as reviewer. Using two model families is deliberate: the reviewer's errors are less correlated with the author's. The records stay model-agnostic.

### 2.3 Why larger items now

Revision 1 cut the work into items a session could finish in one context. The failures were not implementation failures. They were recording and review loops around small PRs (L1, L3). A capable Executor with a large context can carry a whole milestone, provided three conditions hold. The stages are gated, so a wrong turn is caught within one stage. The scope guard catches improvisation mechanically (L4). The evidence is taken once at the end, not per commit (L1). Each packet in §8.1 ends at a milestone Kennedy can accept in one review, with a review index to read it by.

### 2.4 Stochastic generation protocol

Sampling is cheap and verification is the constraint. The protocol exploits the first without weakening the second.

1. **Generate wide, verify narrow.** A generated artifact, whether code, test, fixture, corpus case or document, counts only after a deterministic oracle passes it: the compiler, the lane, the checker, a registered grading, or a property test. Record the generation with `generation = "sampled"`, the model id, a seed or sample index, and the prompt's digest.
2. **The grader is fixed before the generator runs.** Graded cases and their expectations are committed, or committed by digest, before the implementation they grade exists or runs on them (M7). A session never grades its own samples: graded corpora are generated by a separate session that has not seen the implementation. Held-out sets remain Kennedy's (DP-1.1b, DP-1.4).
3. **Best-of-N for decisions, with the losers kept.** For a design choice, such as a boundary decision, a data-structure choice or a witness format, sample N ≥ 3 alternatives. Score each against stated criteria, for example B1 to B4 and D1 to D5 by the checker, and the refutation criterion. Record the winner and the rejected alternatives with their scores in the decision record. Kennedy decides where a gate says so.
4. **Disagreement is a test.** For pure core functions (`slugify`, wikilink resolution, the stats estimators, the verifier's predicates), generate an independent reference implementation in a separate session. Run it against the real one under proptest (differential testing). A difference is a witness to investigate, not a vote.
5. **Adversarial corpora at scale.** Generate, with recorded seeds: several hundred synthetic markdown documents that stress headings, links and anchors (P-A); random crate and module graphs checked against an independent reference checker (P-C); the §17.2 adversarial additions for the verifier (P-B); and survivor explanations for mutation analysis (P-D). Each corpus is registered before it is run (rule 2).
6. **Bounds.** Generation never writes the spec, `.rha/policy.toml`, the grading of a registered corpus, or held-out material. A generated change is a proposal in the change record until its oracle has passed.

## 5. `xtask` design

One crate, lib + bin (integration tests and later `rha-verifier` call the checker in-process). Role `tool`; nothing may depend on it (`dir.tool_depended_on`).

| Module | Responsibility |
| --- | --- |
| `cli` | clap: `architecture [--manifest-path P] [--rules P] [--format text|json|md] [--transitive]`; `ci [--label local|ci] [--record DIR] [--only ID] [--print]`; `l1 [--changed-from REV]`; `corpus run [--level crate|module] [--evidence DIR]`; `evidence subject`; `docs [--check]`; Phase 3 `bench`, `compare`; Phase 4 `rha lint|derive|explain|ledger` |

**Rule ids (stable; used in reports and the corpus manifest):** `class.unclassified`, `class.prefix_role_conflict`, `dir.core_to_adapter` (D1/Law 3), `dir.core_to_app`, `dir.non_root_to_adapter` (D5; dev-kind edges excluded and listed as `harness_edges`), `dir.tool_depended_on`, `effect.core_disallowed_dependency` (Law 5), `effect.core_disallowed_dev_dependency`, `effect.core_build_script`, `effect.core_clippy_template` (W1), `adapter.missing_port_owner`, `adapter.port_owner_wrong_kind`, `adapter.foreign_core` (warn), `meta.unknown_port_owner`, `forbidden.edge`, `graph.cycle`, `transitive.core_disallowed_dependency` (L2), `modules.undeclared_dependency`, `modules.cycle`, `modules.child_to_parent_private`, `modules.foreign_internal`, `modules.unresolved_path` (limitation), `modules.not_implemented` (Phase 1 placeholder → `not_run`).

**Report** `--format json`: `{schema_version, tool{name, version, git_rev}, subject{workspace_root, manifest_path, metadata_mode, rules_path, rules_digest}, classification[], edges_examined{normal, dev, build}, findings[{rule, severity, from, to, kind, manifest_path, witness{edge, declared_in, optional, target}, message}], module_checks[{crate, rules_path, outcome, reason}], limitations[], summary{errors, warnings, outcome}}`. **Exit codes:** 0 no error findings; 1 error findings; 2 usage/config error; 3 environment failure (`cargo metadata` failed) — never a pass; evidence entry `failed`, `error_class: tool_error`.

**`xtask ci` without a second command list:** `.rha/policy.toml [lanes.L0]` carries `source = "docs/spec/rha-spec-v0.10.md §12.1"` and the eight checks with validity criteria (for example `L0.nextest` requires `selected_tests > 0` parsed from the junit file). `xtask/tests/policy_drift.rs` extracts the fenced block that follows `L0 commands (RHA-Rust)` in the spec, strips `#` comments, and asserts equality with the policy argv. `ci.yml` and CONTRIBUTING invoke only `cargo xtask ci`. Outcome mapping: tool absent → `not_run` (`reason: tool_missing`); nonzero → `failed` with `error_class`; zero + validity → `passed`. Overall outcome is the worst check; a `not_run` required check blocks eligibility (§11.4).

## 11. Risks and pitfalls (revision 2)

| Risk | Mitigation |
| --- | --- |
| A large packet hides a wrong turn until review | Stages that end green (M2); gates before irreversible steps; one review index per packet |
| The Executor improvises layout or scope | `cargo xtask scope` before the PR (M4); a widened scope is a quoted decision recorded first |
| Generated tests agree with generated code because one session wrote both | Grader fixed before generator runs; separate sessions for graded corpora; differential oracles (§2.4) |
| A generated corpus is tuned after seeing results | Registration committed, or committed by digest, before the run (M7); failed runs kept; amendments on the ledger and disclosed, as C13's was |
