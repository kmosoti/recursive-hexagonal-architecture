## Deltas

- **Manifest** (protected, approved): C13 gains `expected_findings = [{ rule = "adapter.foreign_core", crate = "adapter-x", to = "core-b" }]`; `[grading] extra_findings` gains one sentence: "A finding matching an entry of a case's expected_findings is a registered fact, neither a detection nor a false alarm." Nothing else changes.
- **Model and validation**: `Case.expected_findings`; a registered fact on a non-detect case, an empty entry, or a prose key is a manifest defect. `xtask/tests/corpus_manifest.rs` pins C13 as the only case that registers a fact, with exactly those three keys.
- **Grading**: `grade::registered` matches by every key. On a detect case a finding that matches the witness is the detection; one that matches a registered entry is a registered fact; anything else is a false alarm. A registered fact never supplies a detection. The grade carries `registered_facts`, and the run summary counts them.
- **Provenance**: the runner records the manifest's amendment chain, pre-registration then EM-M03 (CHG-004) then C13 (CHG-004.6), each link owned by its approval decision, and refuses to run if the manifest's digest is not the last approved one. `xtask/tests/corpus_crate.rs` reconstructs both amendments from the manifest's bytes and checks every digest.
- **Held-out runner**: `cargo xtask corpus held-out --archive <tar>` or `--cases <dir>`, with `--purpose public_control` for exercising it on public fixtures and `--private-dir` for tests. It verifies the commitment (archive bytes, or the committed tar stream re-created for a directory), refuses a mismatched archive, checks archive members before extracting, finds ready workspaces without following links, runs the accepted checker through the same command the corpus uses, prints only opaque ids, exit statuses, counts and the checker's identity, and keeps raw reports and the id-to-path map in a private directory. It grades nothing.
- **Ledger**: DP-1.1c and DP-1.1b amendment keys. **CONTRIBUTING**: one paragraph on the held-out command.

### Test-expectation change under §9.14

Until this item, `xtask/tests/corpus_crate.rs` asserted command exit 1, one unmatched finding, `failed_cases == ["C13"]` and an overall `failed` result, and `xtask/tests/corpus_harness.rs` counted C13's warning as an unmatched finding in the headline. Those assertions were correct for the registration as it stood. The approved amendment changes the requirement, not the observation: the integration test now asserts exit 0, zero unmatched findings, no failed case, an overall `passed` result, 22 detections, both documented holes, and C13's warning under `registered_facts` and nowhere else. The negative controls in `a_registered_fact_is_neither_a_detection_nor_a_false_alarm` show that a changed or missing key is not the registered fact, that an unregistered extra finding still fails the case, that a registered fact cannot stand in for the witness, and that the same warning on C01 is still a false alarm.
