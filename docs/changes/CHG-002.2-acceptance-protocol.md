# CHG-002.2: Acceptance by merge, a decision ledger, and the CHG-002 acceptance record

Task record: [`.rha/tasks/CHG-002.2-acceptance-protocol.toml`](../../.rha/tasks/CHG-002.2-acceptance-protocol.toml). Base: `15d916a`, the merge of CHG-002.

## Intent and scope

Three items in a row ended with the same three open concerns: no acceptance record, decision points unanswered, and the corpus grading values still "proposed". Each was true, and each was a symptom of one defect: the acceptance decision was being made by merging, while every artifact said it had not been made. This change moves the decision into artifacts.

**Behaviour.** A merge into `main` by the acceptance authority is the acceptance (`.rha/policy.toml [acceptance]`). The Executor writes the acceptance record as the first commit of the next item, citing the merge commit, its tree, and the CI record for that revision; creating it is pre-approved, editing an existing one is not. `.rha/decisions.toml` owns decision-point status; a point with a default that is unanswered when its trigger arrives defaults, a required one waits, and reports cite ids rather than restating questions.

**Non-goals.** Checker code. The held-out cases of DP-1.1b, which no agent may author or read. Any lane or strictness change.

### Repair attempts (§11.7.8)

1. **`cargo xtask docs` reported a TOML error and the lane refused the policy.** Two causes, both mine. The task record was written through an unquoted shell heredoc, so a backtick-quoted command inside a string was executed and its output pasted into the record; and `Policy` uses `deny_unknown_fields`, so the new `[acceptance]` section was rejected. Change: the string restored, and an `Acceptance` type added to `xtask/src/policy.rs` as an optional field so a base revision without the section still parses. Result: both parse.
2. **`L0.nextest` failed at the first recorded run (`evidence/CHG-002.2/20260920T020130Z-15d916a16e23-dirty.json`, kept).** Five `corpus::tests` build a manifest fixture inline, and that fixture still said `open_at`. Hypothesis: the same schema change that the committed manifest already carries. Change: the fixture names `decided_by` and `decided_in`. Result: the lane passes `L0.nextest` in the record that follows. The docs were regenerated before each lane run, so each record describes the tree that existed.
